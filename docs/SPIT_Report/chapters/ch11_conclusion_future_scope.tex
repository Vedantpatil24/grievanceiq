\chapter{Conclusion and Future Scope}

\section{Conclusion}
This mini project has conceived, designed, benchmarked, and deployed \textbf{GrievanceIQ}—an enterprise-grade autonomous banking grievance redressal and predictive operational intelligence platform. Built in direct alignment with the APNI Leap framework at Sardar Patel Institute of Technology, GrievanceIQ dismantles the systemic inefficiencies plaguing contemporary Indian banking complaint systems: manual triage latencies, vernacular exclusion, privacy vulnerabilities, and reactive queue management.

By harmonizing a decoupled three-tier architecture (FastAPI, React 18, SQLite), autonomous machine-learning text categorization (Multinomial Naive Bayes, 89.2\% accuracy), zero-latency browser-native voice dictation, statutory DPDP Act 2023 PII masking, dynamic ReportLab QR receipts, and analytical $M/M/c$ queueing models, GrievanceIQ transforms banking grievance redressal into a transparent, secure, and data-driven operational workflow. The entire codebase is verified against 48 comprehensive automated tests with a 100\% pass rate and is open-sourced on GitHub under Version\_6 release tags (\url{https://github.com/Vedantpatil24/grievanceiq}).

\section{Achievement of Objectives}
All six foundational engineering objectives established at the outset of this project were completely achieved:
\begin{enumerate}
    \item \textbf{Autonomous NLP Triage:} Successfully trained and deployed an MNB model on 15,000 real-world banking disputes, achieving 89.2\% categorization accuracy across trilingual inputs.
    \item \textbf{Continuous Vernacular Voice Dictation:} Delivered a non-destructive Web Speech buffer architecture supporting fluent speech transcription in English, Hindi, and Marathi with zero duplicate looping.
    \item \textbf{Statutory DPDP Act 2023 Compliance:} Enforced case-insensitive regular expression sanitization at the API boundary, guaranteeing 100\% masking of Aadhaar, Card, and PAN numbers.
    \item \textbf{Verifiable Statutory PDF Receipts:} Synthesized dynamic ReportLab PDF receipts embedding base-URL-aware ISO/IEC 18004 2D QR matrix codes for instant smartphone tracking.
    \item \textbf{Predictive Capacity Modeling:} Formulated Erlang-C multi-server queue models calculating real-time queue dwell times ($W_q$), traffic intensity ($\rho$), and simulated staffing surges.
    \item \textbf{Explainable AI \& Evidence Verification:} Delivered automated 4-point OCR entity extraction (Amount, Date, Bank, Ref ID) with credibility scoring and structured reasoning traces.
\end{enumerate}

\section{Major Engineering Contributions}
The project makes four primary engineering contributions to applied computer science:
\begin{itemize}
    \item \textbf{Vernacular Voice Ingestion Architecture:} Engineered an isolated-buffer speech pipeline that eliminates the widespread text looping anomaly in continuous Web Speech implementations, enabling truly accessible financial interfaces.
    \item \textbf{Ingestion-Level DPDP Compliance Pipeline:} Demonstrated a privacy-by-design architecture that scrubs sensitive financial identifiers prior to database persistence, shielding institutions from regulatory liability.
    \item \textbf{Closed-Loop Verifiable QR Receipt Integration:} Formulated a lightweight, dynamic PDF generation pipeline that bridges offline paper receipts with online real-time case tracking via 2D barcodes.
    \item \textbf{Bridging Queueing Theory and Bank Operations:} Implemented real-time analytical Erlang-C formulations within a modern web dashboard, empowering branch supervisors with predictive staffing foresight.
\end{itemize}

\section{Current Limitations}
\begin{itemize}
    \item \textbf{Core Banking System (CBS) Mocking:} Due to stringent regulatory firewalls and banking sandbox constraints, transactions are validated against a local relational datastore rather than live production CBS instances (e.g., Infosys Finacle or TCS BaNCS).
    \item \textbf{Single-Node Datastore Scalability:} The current backend employs SQLite in WAL mode. While highly performant for local and mid-tier branch deployments, national multi-million transaction volumes require migration to a distributed PostgreSQL cluster.
    \item \textbf{Browser Speech Recognition Dependencies:} The W3C Web Speech API relies on browser-native speech synthesis engines (predominantly Google Speech in Chromium browsers), requiring active Internet connectivity for high-accuracy vernacular transcription.
\end{itemize}

\section{Future Enhancements}
\begin{itemize}
    \item \textbf{Direct ISO 8583 / ISO 20022 CBS Financial Messaging Integration:} Establishing certified connectors to Core Banking Solutions and the NPCI UPI switch to execute automated debit reversals for verified chargeback disputes.
    \item \textbf{Conversational Voice Bots:} Extending the voice dictation engine into a bi-directional spoken conversational agent capable of guiding illiterate or elderly depositors through interactive verbal interviews.
    \item \textbf{Decentralized Blockchain Audit Trails:} Anchoring grievance lifecycle state transitions into an immutable distributed ledger (e.g., Hyperledger Fabric) to provide tamper-proof dispute histories for statutory banking ombudsman investigations.
    \item \textbf{Federated Learning for Cross-Bank Model Training:} Training category classification models across multiple independent banks using federated learning to preserve inter-institutional customer data privacy.
\end{itemize}

\section{Lessons Learned}
The APNI Leap mini project lifecycle provided invaluable pedagogical and practical engineering lessons:
\begin{itemize}
    \item \textbf{Theory-to-Practice Synergy:} Applying academic concepts from Operating Systems (asynchronous I/O), Database Management Systems (3NF and WAL mode), and Data Structures (sparse matrices and queueing models) proved essential to solving real-world software bottlenecks.
    \item \textbf{The Imperative of Rigorous QA:} Automated regression testing (48 test cases) was pivotal in identifying subtle boundary regressions (such as lowercase PAN masking failures) before release tagging.
    \item \textbf{User-Centric Design in Financial Technology:} True accessibility requires more than aesthetic UI design; it necessitates vernacular language parity, voice-first input modalities, and proactive data privacy safeguards.
\end{itemize}
